# Cross-lane contracts

Every lane must follow these exactly. If a lane needs a change here or in `packages/core`, it does
NOT edit them; it reports the need.

## Ownership

| Concern                                               | Owner                                |
| ----------------------------------------------------- | ------------------------------------ |
| Enqueueing anything (ingest-items, render-jobs)       | `workers/ingest` (cron + reconciler) |
| found -> summarized -> embedded, insufficient_source  | `workers/ingest` consumer            |
| embedded -> voiced -> rendered, transcripts, R2 media | `workers/render`                     |
| Feed, auth, likes, events, Ask, /admin                | `apps/web`                           |

## Requeue rule (`item.queued_at`)

- `queued_at IS NULL` means "needs to be enqueued".
- Ingest cron/reconciler (every 5 min) enqueues: `found`/`summarized` with `queued_at IS NULL` -> `ingest-items`; `embedded` with `queued_at IS NULL` -> `render-jobs`; sets `queued_at = now()` when it sends.
- Same admission policy for every enqueue to `ingest-items` from `found` (score >= `SETTINGS.minItemScore`, today's admitted count < `SETTINGS.dailyReelCap`, pipeline spend today < `SETTINGS.pipelineDailySpendCapUsd`). Skipped items keep `queued_at = NULL` and are re-evaluated next run.
- Items in `found|summarized|embedded` with `queued_at < now() - 30 min` and no progress are treated as stuck: set `queued_at = NULL`, increment `attempts`; after 3 attempts `transitionItem(... to: 'failed')`.
- Admin Retry (web): `transitionItem(failed -> <stage>)` then `queued_at = NULL`.
- Render reconciler: renders stuck in `rendering` > 20 min -> render `failed`, item `queued_at = NULL`.

## LLM quota circuit breaker

A provider quota/billing error (HTTP 402, or 403/429 whose body says quota, billing or RESOURCE_EXHAUSTED) is a pipeline pause, not an item failure.

- `app_setting pipeline_paused` = `{ reason, since, until }` (`SETTINGS.pipelinePaused`; core `getPipelinePause`, `pausePipeline`, `clearPipelinePause`). `until` is the next probe time (15 min).
- The ingest consumer acks the message, sets `queued_at = NULL` and leaves `status` and `attempts` untouched; while paused it releases found/summarized items the same way without calling the provider.
- Reconcile, while paused: skips stuck handling and `found`/`summarized` enqueue (admission). Render enqueues continue. After `until` it makes one cheap embedding call; success clears the pause, a quota error extends it.
- Alert key `llm_quota_exhausted` (deduped hourly). The admin UI may show `pipeline_paused`.
- `scripts/maintenance/requeue-quota-failed.ts [--apply]` moves items failed with those errors back to the stage they failed in (`transitionItem`, `queued_at NULL`, `attempts 0`).

## Papers source

`Source` includes `papers`. Discovery in ingest: Hugging Face Daily Papers (`huggingface.co/api/daily_papers`, upvotes + comments are the score) and arXiv API listings (cs.AI/cs.CL/cs.CV/cs.LG, no score, below the admission floor until a Daily Papers mention scores them). Canonical key `arxiv:<id>` (version stripped, any arxiv abs/pdf/html URL, so HN links dedupe onto the paper), `canonical_url` `https://arxiv.org/abs/<id>`, kind `article`. Evidence: abstract + authors in the mention body; introduction and conclusion from `arxiv.org/html/<id>` in `raw.extraTexts` (fallback only, see Paper parsing service for the structured parse used at summarize time). Settings: `papers_hf_limit`, `papers_arxiv_categories`, `papers_arxiv_per_category`, `papers_max_age_days`. Render labels the source chip "Research".

## Firecrawl fallback (scrape)

Direct fetching is always tried first (papers evidence, HN and news article text). Firecrawl (`FIRECRAWL_API_KEY` ingest secret) is used only when the direct fetch errors, returns 401/403/429/451/503 or a challenge page, or yields text thinner than the threshold; 404/410 never trigger it. Each paid scrape is recorded as `recordSpend(category 'scrape', units 1, costUsd 0.005, meta { url, reason })`, capped by `scrape_daily_spend_cap_usd` (default 1), and the same URL is not scraped twice within 3 days. `scrape` is not part of the pipeline or Ask caps.

## Queues (Cloudflare)

- `ingest-items`: body `{ "itemId": "<uuid>", "attempt": <int> }`. max_retries 3, DLQ `ingest-items-dlq`.
- `render-jobs`: body `{ "itemId": "<uuid>", "attempt": <int> }`. max_retries 3 for most errors, 8 for `container_unreachable` (capped backoff), DLQ `render-jobs-dlq`. Optional `deferrals` counts how often the box answered busy (each busy answer re-sends a fresh message with a 45 s delay instead of retrying).
- Consumers must be idempotent: `transitionItem` throws `StaleTransitionError` on duplicates -> ack and move on.

## Item script and text

- `item.tldr`: <= 280 chars plain text.
- `item.script`: JSON validated by `reelScriptSchema` (core). Written by ingest, read by render. Claims must cite `evidence_chunk.id`s that belong to the item.
- `item.content_hash`: `contentHash([title, tldr, JSON.stringify(script)])`. `item.prompt_version`: ingest's prompt version string.

### Beat sheet (script v7, prompt `reel-v4`)

- `script.headline` (optional, <= 7 words, shown uppercase for the first ~3 s) and per-beat `shots: [{ at, show, props?, sfx? }]` (<= 4 per beat). `at` is a spoken-word cue inside that beat's text: `word` or `word#n` (nth occurrence), case and punctuation ignored. `show` is a `ScreenName`, `sfx` an `SfxName`; the lists live in `packages/core/src/domain/reel-script.ts` and `workers/render/container/remotion/src/lib/types.ts` and a test keeps them equal. Both fields are optional: without shots the renderer's deterministic planner builds them.
- Ingest repair (`workers/ingest/src/pipeline/shots.ts`): headline clipped to 7 words; shots dropped when the cue word is not in the beat text, the screen or sfx is unknown, or a props number does not appear in the item's source text (`1,240`, `1240` and `1.24k` count as one value); narration over 135 words is rejected so the model retries. The ingest window is 100-112 words and at most 760 spoken characters (`NARRATION_LIMITS`, `@reelset/core` `spokenChars`): Aura speaks 14.2-15.7 characters per second in production data and reads digit runs one digit at a time, so digits past the third in a run weigh 4x. 805 characters of text with three 16-19 digit probabilities (item 26ff9540) ran past the 58 s cap in Aura and fell back to edge-tts; the prompt now tells the model to speak numbers with at most 3 significant digits while props keep the source value.
- Container (`reel/validation.py`, `reel/cues.py`): validates the same shape, resolves each cue to seconds against the TTS word times (`scene.shots[].t` in props, unresolved cues dropped with a warning) and passes `headline` through.
- Audio (`reel/mix.py`, `audio/`, generated by `tools/gen_audio.py`): the final mp4's audio is rebuilt after Remotion: Aura/edge narration normalised to -16 LUFS, a deterministic synthesized music bed (4 variants, ~-26 LUFS, picked by job id, looped) sidechain-ducked under speech, and SFX (`whoosh pop tick ding hit riser swoosh`, synthesized, no samples) at cue times: headline pop, a whoosh on every beat start, plus `<job>/timeline.json` shots written by `render.mjs` (`{ shots: [{ t, sfx }] }`; without it the script shots are used), a riser 1.3 s before a ding. Master `loudnorm` two-pass to -14 LUFS integrated, true peak <= -1.5 dBTP (limit -1). A mix failure falls back to the plain remux with the Remotion audio. `meta.mix` reports cues, bed and pre-master LUFS.
- QA: `scripts/qa/qa_reel.py video.mp4 props.json --out qa/` (wraps the vendored `qa_video.py`): average shot <= 2.5 s, none > 4 s (planned and detected), caption pages, frozen stretches, flat frames, -14 LUFS +/-1, TP <= -1.

## Evidence

- `evidence_chunk` rows per mention: thread body + top comments (Reddit/HN), README excerpt (GitHub), transcript (YouTube), article text (news). ~800 chars per chunk, 768-dim embedding via core helpers (raw `sql` with `toVectorLiteral`).

## Transcript service (render worker, service binding `RENDER` in ingest)

`POST https://render.internal/transcript` body `{ "videoId": "<11 chars>" }` ->

- `200 { "status": "ok", "language": "en", "segments": [{ "text": "...", "start": 0.0, "duration": 2.1 }] }`
- `200 { "status": "unavailable", "reason": "blocked" | "no_captions" | "error" }`
  `blocked` / `no_captions` = ingest transitions `found -> insufficient_source` (no fallback, by product decision). `error` (and any non-2xx) = transient: ingest retries the message.

## YouTube discovery service (render worker, same `RENDER` binding)

No YouTube Data API and no API key. Discovery runs in the render container with `youtube-search-python` (pin `httpx<0.28`; channel listing is broken in that library, so discovery is keyword search only).

`POST https://render.internal/youtube/search` body `{ "queries": string[], "maxAgeDays": int, "perQueryLimit": int }` ->

- `200 { "status": "ok", "videos": [{ "videoId", "title", "channelName", "channelId", "url", "publishedAt" (exact ISO from Video.getInfo), "viewCount" (int), "durationSec" (int|null), "description", "thumbnailUrl" }], "failedQueries": string[] }`
- Videos are de-duplicated by `videoId`, filtered to `publishedAt >= now - maxAgeDays`, and only fetched with `getInfo` when the search result's relative time ("3 days ago") is within the window.
- `502 { "status": "error", "reason": "..." }` when every query fails (library broken or blocked) -> ingest marks the youtube task failed and raises `youtube_search_failing`.
  Settings: `SETTINGS.youtubeSearchQueries`, `SETTINGS.youtubeMaxAgeDays`, `SETTINGS.youtubeResultsPerQuery`.

## Paper parsing service (render worker, same `RENDER` binding)

Papers are parsed in the render container (Python: BeautifulSoup+lxml, PyMuPDF, pymupdf4llm, Pillow, optional Ghostscript), not in the ingest worker. Ingest calls it at summarize time for `arxiv:` items, so the cron fetch stays cheap.

`POST https://render.internal/parse/paper` body `{ "arxivId": "2611.08264" }` (version suffix allowed, old-style ids allowed) ->

- `200 { "status": "ok", "paper": ParsedPaper, "stats"?, "cached"? }`; `200 { "status": "failed", "reason": "not_parseable" }`; `502` for container or validation errors; `400` for a bad id. Ingest treats everything except `ok` as "no parsed paper" and falls back to today's behaviour (abstract + regex intro/conclusion from `raw.extraTexts`, then the Firecrawl PDF scrape if that text is empty).
- Storage: R2 `papers/<id>/paper.json` (`/` in old-style ids becomes `_`) plus figure files `papers/<id>/fig-<n>.png|jpg` served from `MEDIA_PUBLIC_BASE_URL` (default `https://media.reelset.app`). The JSON is the cache: a hit with the current `PAPER_PARSER_VERSION` skips the container. No database column; item.images keeps the figure URLs, the table and equation data a reel needs is copied into the shot props when the script is generated.
- `ParsedPaper` (zod in `packages/core/src/domain/parsed-paper.ts`, Python producer in `workers/render/container/reel/paper/`): `title, authors, affiliations, abstract`, `sections[{heading, level 2-4, kind: abstract|intro|related|method|experiments|conclusion|appendix|other, markdown}]` (flat, direct content only; math as `$latex$` from the MathML alttext, citations and footnotes removed), `tables[{id, label ("Table 2"), caption, headers[], rows[][], best[[row,col]], second, bestBy: bold|computed|none, notes}]` (multirow/multicol expanded onto the grid; group headers are joined onto leaf columns; `bold` = bold in the source, `computed` = per-column best from explicit up/down arrows when nothing is bold), `figures[{label, caption, url, width, height, hires, origin: eprint|latexml|pdf}]`, `equations[{latex, label}]` (up to 6 numbered display equations), `links[{kind: code|project, url}]`, `markdown` (compact rendering), `source: html|pdf`, `version`.
- Parse order: (1) `arxiv.org/html/<id>` LaTeXML with a real DOM parser; (2) hi-res figures from `arxiv.org/e-print/<id>` (tar.gz, 60 MB cap): `\input`/`\include` are expanded, `\begin{figure}` blocks give `\includegraphics` + `\caption` + `\label`, captions are matched to the HTML figures by similarity (order if counts agree), PDF figures are rendered with PyMuPDF at about 1600 px wide and cropped, rasters are kept (no upscaling), EPS needs Ghostscript (skipped if absent); LaTeXML copies stay for anything not converted; (3) no HTML: `arxiv.org/pdf/<id>` via pymupdf4llm (markdown, pipe tables, sections) plus embedded images of at least 420x240, and e-print figures when available. If all of that fails the container answers `failed`.
- Etiquette: arXiv hosts only, one request at a time with a 3 s gap, user agent `reelset-paper-parser/1.0`, size caps, a time budget of 85 s in the container (the worker waits 110 s). e-print is skipped when under 25 s remain.
- Evidence for the LLM (`paperEvidenceTexts`): introduction, method, experiments/results, the main results table as markdown (best cells in bold, label and caption included) and the conclusion, about 11k characters at most. A `PAPER_ASSETS` prompt block lists real table, figure (with image index) and equation labels.
- Shots: `TableScreen {table, row?, metric?}` and `EquationScreen {equation, label?}`, plus `FigureZoom {figure?}`. After generation `resolvePaperShots` replaces the references with renderer props (`TableScreen`: `ref, caption, headers[<=4], rows["a|b|c"...<=6], hi, col, value, label, best["r:c"...]`; `EquationScreen`: `latex, label`; `FigureZoom`: `image` index) and drops shots whose reference does not exist; both paper screens are dropped for items without a parsed paper. Table props use flat strings and numbers only because the container validator rejects nested lists deeper than two levels and booleans.
- Remotion: `TableScreen` (rows pop in, the best row gets a sweep, the key number counts up, 3 value columns and 6 rows at most) and `EquationScreen` (KaTeX, static, scaled to fit). They hold 2.6 s and 2.2 s before the next cue and are kept up to 5.4 s and 4.8 s (`lib/table.ts`). `FigureZoom` never shows an image above 1.2x its pixels and keeps the whole figure in frame.

## Render output

- R2 bucket binding `MEDIA`. Keys: `reels/<itemId>/<renderKey>.mp4`, `reels/<itemId>/<renderKey>.jpg`.
- Video: 1080x1920 30 fps H.264 (~3 Mbps), `+faststart`, AAC, captions burned in at 58-72% of frame height (centered, 72% wide, 2 lines max; `theme.ts` is the single source) so they clear the app bottom overlay and right rail, <= 60 s, <= 25 MB.
- `render` row: unique `render_key` = core `renderKey({ itemId, contentHash, promptVersion, templateVersion, voice })`; `status done` with `video_key`, `poster_key`, `bytes`, `video_duration_ms`, `render_ms`.
- Retention: renders whose item `published_at` is older than `SETTINGS.reelRetentionDays` get their R2 objects deleted and `video_key = NULL`.
- Public URL = `MEDIA_PUBLIC_BASE_URL + "/" + video_key`.

### Render engine (the box)

The render worker calls the boxes in `BOX_URLS` over HTTPS with `Authorization: Bearer RENDER_BOX_TOKEN` (`GET /health` open); same paths and bodies as the former Cloudflare Container. One render at a time (`MAX_RENDERS`, default 1): a second job gets 429 `{"error":"busy"}` and a repeat of the running job gets 409 `{"error":"in_progress"}`; the worker retries both later without counting a failure. `GET /render/<jobId>` returns `{"state": "running"|"done"|"absent"}`.

Python server (`/health`, `/transcript`, `/youtube/search`, `/render`) orchestrates; frames come from a Remotion 4.0.540 composition (`workers/render/container/remotion`, React 19) that is bundled at image build time and rendered with `@remotion/renderer` by `remotion/render.mjs`. FFmpeg only remuxes (`+faststart`) and cuts the poster.

`POST /render` body: `{ jobId, script, title, sourceLabel, voice, imageUrls[], source?, canonicalUrl?, sourceImageUrls[]? }` (extra fields such as the legacy `illustrate` are ignored). Response adds `cover: bool` (default false).

- Timing: edge-tts word boundaries drive everything. Scene spans come from `timing.allocate_segments` (hook, one scene per beat, outro); captions page the same words with punctuation restored (`reel/words.py`); the poster is cut at the end of the hook.
- Scenes: kinetic hook, `title`, `code` (syntax highlight + typing), `stat` (count-up), `quote`, `image` (Ken Burns), outro with source and `reelset.app`. Content stays inside the app-UI safe zone (not in the bottom 22% or right 15%).
- Imagery (best effort, never fails a render): `sourceImageUrls` are direct URLs tried in order (GitHub social preview `opengraph.githubassets.com/1/<owner>/<repo>`, YouTube `i.ytimg.com` thumbnails; worker derives them in `plan.sourceImageUrls`). Otherwise the container reads `og:image` from `canonicalUrl` (https, every resolved address must be globally routable, redirects re-checked, <= 5 MB). Script `image` beats use the `imageUrls` allowlist (`github`, `ytimg`). Missing assets fall back to a generated cover.
- TTS provider: app_setting `tts_provider` (`edge` default | `aura2` | `kokoro`) and `tts_aura_speaker` (default `hera`). `aura2` runs in the render worker through the `AI` binding: `@cf/deepgram/aura-2-en` (mp3, $0.03 per 1k chars, text chunked on sentence boundaries at 1500 chars) then `@cf/deepgram/nova-3` on the audio ($0.0052/min) for word times, which `alignWords` maps onto the script's own tokens (LCS anchors on normalized words; numbers, hyphenated terms and ASR slips share their gap's time window; under 50% anchors falls back to per-character timing). The worker POSTs `narration: { audioBase64, words: [{ text, start, end }] }` in the `/render` body (container limit 8 MB) and the container skips edge-tts and punctuation restoration. The render-key voice is `aura2-<speaker>` (edge keeps `TTS_VOICE`), so switching provider or speaker re-renders via the template upgrade cron. Any Aura failure (Workers AI error or quota after 2 attempts per call, empty audio, Nova failure, under 50% word anchors, or narration still over 58 s after the one shortened retry) falls back at once, on the same delivery, to the container's Kokoro then edge-tts chain (see Kokoro fallback); there is no longer a wait for the 3rd delivery. Spend: `tts` row with cost chars x $0.00003 + audio seconds x nova rate for Aura, 0 for Kokoro and edge; `meta.provider` is `aura2`, `kokoro` or `edge` (what the container reports as `ttsProvider`). Aura characters paid for a discarded narration are not recorded. Helper: `scripts/smoke/aura/aura.mjs`.
- Kokoro fallback (`reel/kokoro_tts.py`, `lexicon.py`, `kokoro_timing.py`, `narrator.py`): `POST /render` accepts `ttsEngine: 'kokoro' | 'edge'` (default `edge`) when no `narration` is supplied. The worker sends `kokoro` unless `tts_provider` is `edge`, and `kokoro` as the primary when the setting is `kokoro` or `aura2` has no `AI` binding. `Narrator` tries Kokoro, and on any `KokoroError` (model missing or load failure, synthesis error, no phoneme timings, over the cap even at speed 1.25) falls back to edge-tts for that render, including edge's faster-rate retry. `/render` metadata adds `ttsProvider` (`kokoro | edge | supplied`). Model: kokoro-onnx 0.6.1 (MIT) with the fp16 model (`kokoro-v1.0.fp16.onnx`, 164 MB) and `voices-v1.0.bin` (28 MB) from release `model-files-v1.1`, downloaded at image build into `/opt/kokoro` and pinned by sha256 in the Dockerfile (`ADD --checksum`); weights Apache-2.0, espeak-ng G2P (GPL-3.0, bundled by `espeakng-loader`, backend only). Voice `af_heart`, 2 onnxruntime threads, loaded lazily once per process (~0.7-0.8 GB peak). Speed starts at 1.15 (about 129 wpm incl. pauses; faster clips sentence starts) and a measured result over 58 s is re-synthesized once at the speed that fits, never above 1.25. mp3 is 24 kHz mono 128k via ffmpeg with `loudnorm=I=-15:TP=-1.5` applied first. Pronunciation: `lexicon.spoken_form` rewrites each script token before phonemizing (a data table: MOPD, DKIM, DMARC, nginx, kubectl, sudo, SQLite, PostgreSQL, OAuth; rules: `P^2`/`P²` squared, `1.7B` billion, `.com .org .net .dev .app` as "dot", `.js .ai .io` spelled, `a=b` equals, consonant-only all-caps tokens such as SPF or TCP spelled by letter; words with vowels such as NASA are left to espeak). Timings: each script token is phonemized on its own and `kokoro_timing.regroup` maps the model's per-phoneme timings back onto the ORIGINAL token (whitespace-insensitive alignment, difflib on divergence, trailing punctuation excluded from the span, empty tokens collapse to zero length), so the output is one monotonic `{text, start, end}` per script token, the same shape `alignWords` gives, and no Nova call or punctuation restoration is needed.
- Source images (v6): ingest stores `item.images` (jsonb, max 6: `[{url, kind: og|thumbnail|figure|screenshot|avatar, width?, height?, alt?}]`, null = not captured) at summarize time (`workers/ingest/src/images.ts`; backfill `scripts/maintenance/backfill-item-images.ts`). Render loads it via `ItemForRender.images` and sends `images` in `POST /render`; the container (`reel/source_images.py`) downloads https public URLs (<= 8 MB, image/*, gif <= 5 MB), drops < 240x140 / extreme aspect / blank / near-duplicates, re-encodes JPEG (<= 1280px, never upscaled) as `assets/img<N>.jpg`, and passes `props.images = [{src: 'job/img<N>.jpg', kind, width, height, alt?}]` (+ `cover` = first). Remotion shows the hero in the hook (play badge for YouTube), figures/screenshots in image beats with a source caption, and falls back to drawn motifs when none. Items without `images` fall back to `sourceImageUrls`/og:image as before.
- No AI/LLM image generation in rendering. All visuals are code-drawn Remotion/SVG motion graphics (`remotion/src/art/*`): the motif (network, terminal, git graph, bars, paper, video timeline, discussion thread) is chosen deterministically by `lib/art.ts` from source, title/script keywords and beat visual types. Real source imagery (YouTube thumbnail, GitHub social preview, og:image) is fetched best-effort and shown only as a small source card in the outro; a reel renders identically with zero external images. Render spend is `tts` + `render` rows only.
- `TEMPLATE_VERSION` (worker `constants.ts`) is part of the render key. Bumping it re-renders: the render worker's 5-minute cron tops re-renders up to 6 renders in flight (`UPGRADE_IN_FLIGHT_TARGET`): it queues `rendered` items with no render row for the current key, minus `rendering` renders, upgrades it sent in the last 15 min that have not started (tracked in `app_setting.render_upgrade_sent`), and the backlog of new `embedded`/`voiced` items, so new items keep priority, and the consumer renders `rendered` items without changing their status, so the old reel stays in the feed until the new `done` render (latest `finished_at` wins) replaces it.

### Template 7: beat-sheet composition (1080x1920, 30 fps)

Replaces the card-on-empty-background look with full-bleed screens cut on spoken words.

- Script contract: `script.headline` (<= 7 words, rendered uppercase in a 0-3 s accent card) and per-beat optional `shots: [{ at, show, props?, sfx?, t? }]`. `at` is a spoken-word cue (`word` or `word#2`); the container resolves it to `t` seconds (`reel/cues.py`), the composition falls back to its own matching (`lib/cues.ts`, exact then prefix) and, if a cue is missing, logs `[plan] ...` and uses planner timing. Never fatal. `show` is `ScreenName`, `sfx` is `SfxName`; both enum lists live in `remotion/src/lib/types.ts` and `reel/validation.py` (keep in sync).
- `ScreenName`: RepoPage, Terminal, CodeBlock, StatSlam, BarRace, HNThread, RedditPost, YouTubePlayer, PaperPage, FigureZoom, ArticleHeadline, ImageFull, KeyPoint, Compare, EndCard. Common props: `image` (index into `props.images`), `value`/`label`, `text`/`sub`, `lines`, `code`/`language`, `bars`, `left`/`right`, `phrase`, `quote`/`by`.
- Without shots, `lib/planner.ts` plans deterministically: chunks of 1.5-2.5 s on word boundaries (preferring punctuation), a screen per chunk from the beat visual, numbers in the narration, item facts and images; no screen repeats back to back, a real image at least every ~5.5 s when `images` exist, nothing held over 4 s, EndCard last.
- Optional `facts` in the `/render` body (real item metadata, whitelisted in `validation._validate_facts`): `repo {owner,name,description,stars,forks,language,languages[{name,pct}],topics}`, `hn {points,comments,author,topComment}`, `reddit {subreddit,upvotes,comments,author}`, `youtube {channel,views,duration}`, `paper {authors,abstract,upvotes}`, `article {site,author}`. Screens only show counts that exist here or in the script; callers (render worker) should pass them when known.
- FX: Punch (1.1 -> 1 plus white flash, 6 frames) on every cut, Drift on holds, Pop on cards and rows, vignette and grain.
- Captions: 1-4 word pages, heavy white outline text with the spoken word in an accent box, inside the 58-72% band (776 px wide). Top chrome (progress, source chip, wordmark) starts at 12% (230 px).
- The composition writes `<job>/timeline.json` (`{ fps, shots: [{ t, seconds, show, sfx, origin, scene }] }`) for the audio mix. `riser` lead-ins are added by the mix before `ding` cues.
- Video bitrate is 3000k at 1080x1920 (60 s stays under 25 MB).
- Facts (render worker `facts.ts`): built from stored mentions only (score/num_comments/author + `mention.raw.facts` captured at ingest: github forks/language/topics/latestRelease, HN topComment, reddit subreddit, youtube durationSec). Missing fields are omitted. Backfill: `scripts/maintenance/backfill-mention-facts.ts`; regenerate scripts for feed items with the current prompt: `scripts/maintenance/regen-scripts.ts` (status untouched; render cron upgrades on the new content hash).
- Transitions (`lib/transitions.ts`): deterministic punch / slide / whip / cut / rise per cut, first shot none; flash only on punch. A thumbnail is shown big once.
- Render budget: Remotion concurrency defaults to min(2, cpus) (measured fastest; jpeg quality and x264 preset made no difference); `REMOTION_TIMEOUT_SECONDS` 780, worker `RENDER_TIMEOUT_MS` 14 min (queue consumer wall limit is 15), stuck reaper 30 min.
- Aura over 58 s: before any synthesis `speakableNumbers` rewrites decimals with 4+ fraction digits to 3 significant digits (hook, beats, outro and shot cues; props are untouched) for every engine. An over-cap narration is re-synthesized up to 2 times from a script cut to (58 - 5 s) / measured seconds (`shortenScript`: trailing sentences of the longest beats first, then whole beats, never the first beat, never below 3), then Kokoro, then edge-tts.
- Kokoro speed refit (`kokoro_tts.refit_speed`): pauses do not shrink with speed, so time is modelled as pause + speech / speed. One measurement assumes a 20% pause share, two solve it exactly; up to 3 renders, speed capped at 1.25, otherwise `KokoroError` and edge-tts.
- Render consumer retry: when a delivery fails and a retry is scheduled, `markRetryPending` puts the render row back to `queued` so the 20-minute stuck reaper does not fail a render that is only waiting. The item title sent to the container is clamped to its 200-character limit (`containerTitle`; longer HN titles used to fail as `invalid_input`).

### Template 8: variety, grounded labels, b-roll, demo clips

- Planner variety (`remotion/src/lib/planner.ts`, `variety.ts`): per reel each screen look is used at most twice (`EndCard` once; the demo is placed by the hook and demo rules below), a KeyPoint layout (left / uppercase / right) and a b-roll backed variant count as separate looks, a hero image or screenshot appears once and a wide figure at most twice in two different crops (never back to back), and the same screen never repeats within 3 shots. `enforceVariety` re-picks (or folds into the previous shot, holds <= 4 s) every shot, planned or cued, that breaks a rule; when sources are exhausted it keeps the shot rather than leave a hole (best effort, never fatal).
- Grounded labels (`lib/labels.ts`, `lib/ground.ts`; mirrored in `workers/ingest/src/pipeline/stat-labels.ts` for script repair): a StatSlam / BarRace label must sit within 6 words of its number in that scene's narration; otherwise it is rewritten from the words next to the number, a label is never reused for a different number in one reel, and a shot with no honest label becomes a KeyPoint. `TableScreen` labels default to `<row> · <column header>` from the table cell. The ingest prompt (`reel-v4`) says the same and repair applies it with a ledger shared across beats.
- Display fixes: StatSlam and BarRace values go through `lib/stat-format.ts` after grounding (decimals with 4+ fraction digits round to 3 decimals, 3 significant digits below 0.1, so `valueOf` matches the original; a bare 0-1 probability with a probability/confidence/chance label reads as a percent). List cards keep the kicker on one line (`kickerSize`) and item text inside the column beside the bullet (`listTextWidth`), clear of the 86% safe edge. Fonts: Geist, then Noto Sans CJK (`fonts-noto-cjk`, OFL, Regular and Bold only) in the container image, so Chinese, Japanese and Korean text is not tofu.
- Text: KeyPoint text goes through `lib/typeset.ts` (`P^2` -> `P²`, `H_2O` -> `H₂O`, no character is dropped) and `fitWords` sizes the widest word to the frame (uppercase widths included). Count pills (GitHub stars, forks) are hidden when the fact is missing.
- Key point rules (`lib/caption-echo.ts`, `polish.ts`; `lib/text-rules.ts` is shared with ingest and unchanged): a KeyPoint shows only a statement in sentence case (the script's `props.text` when it is a valid claim, else a short claim from the script), and never a near-verbatim copy of the captions on screen (content words >= 75% in the shot's caption window, looking back 1 s). Keyword fragments ("linear combination", "expert weights", "bounced emails") are never synthesized: the former terms card is gone, a list card (`items` + `kicker`) exists only where the narration speaks a labelled list. A text with nothing honest to say becomes footage (below) or another look (source image, figure crop, stat, list). A last pass (`vetKeyPoints`) re-checks every text against its final span.
- Fill rule (`lib/fill.ts`, `screens/text.tsx`): no screen leaves more than half of the safe area (below the chrome to 82%) empty for more than 1.5 s (`sparseShots`, unit-tested on the sample reels). A text card is the statement set as large as the room allows plus a context plate under it (source chip, item title, and one big real count from the facts: stars, points, upvotes, views); a text-less shot without footage is the full-height plate. Footage, images, cards and charts fill by design.
- Hook rule (`lib/hook.ts`, applied after grounding): the first shot stops the scroll, strongest first: the README demo playing, the hook's own number that no later scene repeats (a StatSlam), a full-bleed real image (photo or portrait/square picture; a wide share card, paper thumbnail or figure never), a big real count from the facts (HN >= 150 points, Reddit >= 500, GitHub >= 1000 stars, paper >= 50 upvotes), else the headline itself set huge over the story's image (`KeyPoint` with `hook: true`, replaces the headline slab). Never a source card, a small thumbnail in a blurred surround or caption-only footage. The first shot runs at most 2.4 s and nothing is folded into it.
- Stock b-roll (Pexels): render worker `pexels.ts` picks up to 20 candidate clips per reel (at most 14 survive the container). Terms: the beat's optional `broll` (<= 2 lowercase abstract phrases from the script; brands, product names and words from the item title are rejected) else every matching keyword-map entry, topic before tooling (email, security, images, DNS, terminal, server, hardware, network, database, models, code), else a per-source default list, plus generic tech fillers. Search: portrait, `size=medium`, 30 results per term, >= 1080x1920 mp4, 4-45 s, cached 7 days in R2 (`cache/pexels/search-30-<sha1>.json`), 180 requests per hour budget (`cache/pexels/rate.json`; past it only cache is used). Round one gives each beat a clip, later rounds add more per beat until 20. Concrete queries (`broll-relevance.ts`): abstract terms map to unambiguous Pexels searches (`network cables` -> `ethernet cable`, `server room` -> `server rack`, `circuit board` -> `electronic circuit board`). Relevance filter: a clip whose page slug has a people, vehicle, city, soldering, trading-chart, hallway or gym word is rejected, and a described clip must name the term or a tech-scene word (a slug with no descriptive words passes). Ranking (`clipScore`): people-centric stock clichés (slug words like woman, man, hands, typing person) and matches in the wrong world (restaurant "server", cable "cars") rank behind footage of the thing, a slug naming the term ranks first, then Pexels' own order. Diversity: never the same clip twice in a reel (the composition guarantees it too: `assignBroll`, `dropRepeatedClips`, test `repeatedClips`); across reels the ids used by the last 8 reels (`cache/pexels/recent.json`, additive, newest last) are skipped unless nothing else fits, then the least-used clip first (`cache/pexels/usage.json`). The worker sends `broll: [{url, id, beat (scene index), seconds, creator, creatorUrl, pageUrl}]` in `/render`; the container (`reel/media.py`) downloads `videos.pexels.com` only (<= 25 MB, 4 at a time), rejects unusable clips and logs `broll rejected id=<id> reason=<why>`: too dark (median luma over 2 fps samples of the used 6 s below 38 of 255, ffmpeg `signalstats` YAVG) and too blurry or featureless (median positive-Laplacian edge energy below 1.8, `convolution` + `signalstats`; sharp frames score 3-14, out-of-focus under 2); thresholds were set on the v11 clips and are unit-tested on synthetic frames. Burned-in text is not detected. It keeps at most 14 good clips, trims to <= 6 s, strips audio, 720x1280 30 fps h264, and passes `props.broll`. Remotion `Backdrop` plays a clip (`OffthreadVideo`, muted, opacity 0.4) under KeyPoint / StatSlam / Compare / EndCard behind a dark scrim and a faint grade; every footage-only shot gets a clip of its own first (a shot held over 2.9 s is cut into pieces that each need one), two clips stay free for later passes, then text shots, and the clip for a beat goes to a shot of that beat first. A clip is never shown twice: when the clips run out the shot becomes another look (a source image, figure crop, stat, list), is absorbed by a neighbour (holds <= 4 s), or, as the last resort, shows the full context plate with its own `ambient` variant. No `PEXELS_API_KEY`, no hits or any failure means no b-roll and a normal render.
- Attribution (Pexels terms): the web Sources sheet must show a prominent "Videos provided by Pexels" link (`https://www.pexels.com`) and "Video by <creator> on Pexels" linking to each clip page. Source of truth: `render.credits` (jsonb, additive migration `20261110010000_demo_clip_render_credits`) = `[{ kind: 'stock', provider: 'pexels', creator, creatorUrl, url }, { kind: 'demo', repo, url }]`, written by `markDone` from the container's `meta.credits`, which lists only media that actually appears (`timeline.json` `usedBroll` / `usedDemo`). The web lane reads `render.credits` of the latest done render with the feed item and renders the lines.
- Demo clips: ingest `demo.ts` reads the README, finds `<video>`, `github.com/user-attachments/assets/...`, repo or `raw.githubusercontent.com` videos and GIFs (badges, logos and other hosts skipped), probes type and size with a ranged GET (<= 20 MB, GIFs >= 60 KB) and stores `item.demo = { url, kind: gif|mp4|webm, bytes? }` (`{ none: true }` once checked). Backfill: `scripts/maintenance/backfill-item-demo.ts [--apply]`. The worker sends `demo: { url, kind, repo }`; the container converts a 6 s stretch to mp4 (<= 1440 wide, no audio) and passes `props.demo` with `static`, `focus` and `content`. The stretch is the most visual one: among runs of real UI (no title card, fade or blank, by edge density) it takes the window with the most motion (ffmpeg scene scores at 2 fps), so a gallery filling in beats a static form; a window that barely moves (< 0.004) sets `static: true`. `focus` is the densest cell of a 3x3 edge-energy grid and `content` the horizontal extent of the UI (Pillow-free, raw gray frame). `RepoDemo` is a planner-only screen (not for the LLM; cue shots naming it without a demo are dropped). It opens the reel (hook rule) and returns where the narration points at it; all its cuts together play 3-5 s (`stretchDemo`), each cut a different crop (`part` 0 then 1, or both halves of a single shot). The window (`lib/demo.ts`) is 799 px wide (x 11-86%) and 64% of the frame tall, over a blurred copy of the clip: cut 1 starts at the left edge of the UI so its heading is whole and pans at most 18% of the width; cut 2 zooms 1.3x on the densest region; a static demo does not pan and zooms into its text. Chip "Demo · github.com/owner/repo".
- Image vetting (`workers/ingest/src/pipeline/image-vet.ts`): at capture time each candidate image (<= 6 per item) is sent to the Claude model in app_setting `image_vet_model` (default `claude-haiku-5-5`, `createClaudeVetter`, base64 image block, `effort: low`); the answer `{keep, reason, role: hero|figure|screenshot|logo|junk, caption <= 60, text <= 400, focus {x, y}}` drops junk, logos and keep=false (except for a Reddit post's own images, which are only annotated: a meme or screenshot is the subject), and `role`, `caption`, `text` (words and numbers read in the image) and `focus` are stored on `item.images[]` (`captionFor` prefers the caption, `focusOrigin` aims the Ken Burns zoom). Cached per URL hash in `app_setting` (`img_vet:v2:<sha256 prefix>`), at most about $0.004 per item on Haiku (the per-item cap is counted in Haiku-priced units, so on Sonnet or Opus it still allows the same images per item and real cost scales with the model; vet calls are not booked as spend rows). A 402 or quota error, an invalid answer or a failed download leaves the image unvetted (never a pipeline pause).
- End card (`lib/endcard.ts`): the name big (repo `owner/repo`, a paper's short name, else the headline), under it a clean subtitle: a repo shows its description (first sentence, <= 90 chars; never the item title, which is often a raw release or commit title), a paper its title without the leading short name, anything that repeats the name or headline is dropped, always sentence-cased.
- Safe zones: everything stays inside x 11-86% at every frame: cut transitions scale in from 0.96 / 0.985 instead of 1.1 / 1.03 (content never crosses the 11% line on the way in), the top-right brand chip keeps 16 px inside the 86% line and right-aligned accent bars 14 px.
- `TEMPLATE_VERSION` 9 (`workers/render/src/constants.ts` and `reel/version.py`). `scripts/maintenance/render-template-counts.ts` and `render-upgrade-status.ts` compute keys with the live voice (`aura2-<speaker>` when `tts_provider` is aura2, `kokoro-af_heart` when it is kokoro).

## LLM + embeddings

- Gemini is used for embeddings only: REST API via `fetch` (no SDK). Env: `GEMINI_API_KEY`, `GEMINI_EMBEDDING_MODEL`. Embeddings requested with `outputDimensionality: 768`. Scripts, image vetting and Ask answers run on Claude.
- Ask (web, `apps/web/src/lib/ask`): Gemini is used only to embed the question (`gemini.ts`, `GEMINI_API_KEY`, `GEMINI_EMBEDDING_MODEL`, 768 dims, `RETRIEVAL_QUERY`). The answer streams from Claude (`claude.ts`, `@anthropic-ai/sdk` `messages.stream`, secret `CLAUDE_API_KEY`, model from app_setting `ask_model`, read per request, default `claude-haiku-5-5`) with `output_config.effort: low` (the answer restates evidence already in the prompt, and thinking delays the first streamed word), `max_tokens` 8000 as a ceiling for thinking plus the ~300-token answer, one SDK retry, 20s request timeout and a 45s whole-stream deadline. The system prompt (`prompt.ts`) is under the 512-token cache minimum, so it carries no `cache_control`; never temperature, prefill or `budget_tokens`. Errors are `ProviderError`s (`provider-error.ts`) whose `unavailable` flag picks the "AI temporarily unavailable" message: no status, 5xx, 401/402/403/408/429 and credit-balance 400s are unavailable; a refusal or a plain 400 is the generic error. Spend guard prices: the answer is priced by its model with `claudeCostUsd` from the shared core table (`packages/core/src/domain/claude-model.ts`) and the `ask` spend row's `meta.model` records it; gemini-embedding-001 $0.15 per MTok (`pricing.ts`).
- Script LLM (ingest, `pipeline/llm.ts`): Claude only, model from app_setting `script_model` (default `claude-haiku-5-5`) and effort from `script_effort` (`low|medium|high`, default `medium`), both read once per queue batch (`loadLlmModels`) and logged as `llm models selected`; secret `CLAUDE_API_KEY`. The Anthropic client (`pipeline/claude.ts`, official `@anthropic-ai/sdk`, bundles for Workers) sends the rules as a cacheable system block (`cache_control: ephemeral`, above the 512-token minimum), the item as one user turn and `output_config.effort`; never temperature, prefill or `budget_tokens` (all 400 on the 5.5 models). Adaptive thinking stays on at `medium`: the script needs grounded numbers and a sharp hook, `low` skips the self-checks that keep narration at 110-125 words, higher levels cost more output tokens with no gain seen. Output is plain JSON through the shared repair/rejection loop (structured outputs are not used: the script schema is a deep union with length limits that JSON-schema grammars do not enforce). Errors: 401, 402 and credit/spend-limit 400/429 raise `QuotaExhaustedError` (pipeline pause + alert); plain 429/529 are retried by the SDK then fail the attempt; `stop_reason: refusal` or `max_tokens` throws `ClaudeError`. Cost (`claudeCostUsd(model, usage)` in core, one table for ingest and web, list prices per MTok): Haiku 5.5 $0.10/$0.50 up to 100K prompt tokens ($0.50/$2.50 above), cache reads 0.1x; Sonnet 5.5 $2/$10, cache reads $0.10; Opus 5.5 $4/$20, cache reads $0.20; cache writes 1.25x input. A Haiku reel script costs about $0.004-0.007. Admin model choices: `/admin/settings` dropdowns (`script_model`, `script_effort`, `image_vet_model`, `ask_model`, `tts_provider`). Reddit posts (`reddit:` items): the post's own images (gallery and in-text `media_metadata` rebuilt as `i.redd.it` originals, a direct image link, or a video/link post's preview frame; up to 4) are attached to the script call as image blocks before the text, listed by index in `ITEM_IMAGES`, and what the vetter read in them becomes an evidence chunk ("Image N in the post: ... Text in the image: ...") the script can cite. A 400 about an attached image retries the call text only.
- Script prompt `reel-v6` (v5 plus the 100-112 word / 760 spoken-character window and the spoken-numbers rule) (`pipeline/prompt.ts`): hook engineering rules plus a style guide in the system prompt (number-led / before-after / contrarian / "you" hooks, banned openers, three drafted hooks and only the best output, headline agrees with the hook, specific takeaway, no padding with repo stats, notation kept as written). The user prompt starts with a `SOURCE BRIEF` (`pipeline/brief.ts`, inside `<untrusted_source kind="brief">`): paper = title, authors, one-line claim, numbers stated in the abstract, KEY RESULTS rows per table with `[section]` prefixes so model sizes and settings never mix, figure captions; github = description, stars, forks, language, topics, latest release notes, install commands, README feature bullets, demo clip yes/no, discussion post numbers; hn = points, comments, date, linked article lead and key numbers, top comments (Algolia items API); reddit = subreddit, score, post text, top comments (direct `.json`, then Arctic Shift, then Firecrawl; Firecrawl does not support reddit); news = headline, outlet, date, lede, key numbers. `brief-fetch.ts` `enrichItem` fetches live comments / GitHub stats, release notes and README before generation and appends them as evidence texts, so every brief fact has a citable chunk; the brief text also counts as source text for number grounding. Narration is enforced at 100-112 words and 760 spoken characters (`NARRATION_LIMITS`). Beats may carry `keyPoints` (1-2 readable 3-8 word statements, optional schema field); KeyPoint shots must be such statements (`readableKeyPoint`: sentence case, adds something the narration does not say), else a beat candidate, else the old noun-chunk repair.
- Scraped text is untrusted data: wrap it in delimited blocks, tell the model to ignore instructions inside it, and post-validate outputs.

## Render director (AI-drawn scenes, Skia renderer)

The render worker asks the box to let Claude write the reel's illustration code (JavaScript drawn on a Skia canvas), review rendered frames once, then render. Everything the model sees is configured at `/admin/director`.

- Settings (`app_setting`, core `SETTINGS`): `director_enabled` (default true), `director_model` (default `claude-haiku-5-5`), `director_effort` (`low|medium|high|xhigh|max`, default `medium`), `director_review` (default true), `director_max_tokens` (1024..128000, default 128000), `director_rules` (200..20000 chars, default `DIRECTOR_DEFAULT_RULES`), `director_review_prompt` (50..6000 chars, default `DIRECTOR_DEFAULT_REVIEW`). Defaults live in `packages/core/src/domain/director.ts`.
- Table `director_skill` (migration `20261113000000_director_skills`, RLS on): `id, name (unique, 1..80), kind ('skill'|'example'), content, enabled, sort, created_at, updated_at`. Admin CRUD at `/admin/director`; seed from local skill folders with `scripts/maintenance/seed-director-skills.ts`.
- `POST /render` gains an optional `director` (core `directorPayloadSchema`, built by `loadDirectorConfig`): `{ model, effort, maxTokens, review, rules, reviewPrompt, skills: [{name, content}], example: string | null }`. `skills` are the enabled `kind = 'skill'` rows ordered by `sort, name`; the total content is capped at 600000 chars (the first skill that would overflow and all after it are dropped and logged by name). `example` is the first enabled `kind = 'example'` row. The field is omitted when `director_enabled` is false or the config fails to load; the box then uses its built-in non-AI Skia renderer.
- The `/render` metadata gains an optional `director` (core `directorMetaSchema`, parsed leniently, never fails a render): `{ used, model, scenes, sceneErrors, fallbackReason, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens, ms }`. `fallbackReason` is `null` or e.g. `disabled`, `no_api_key`, `api_error`, `load_error`, `timeout`, `crash`.
- The worker stores that object in `render.director` (jsonb, written by `markDone`) and records a `spend_ledger` row `category = 'llm'`, `meta = { model, provider: 'anthropic', stage: 'director', renderKey }`, cost from `claudeCostUsd` (cache tokens included; Haiku 5.5 moves to $0.50/$2.50 per MTok when input + cache read + cache write exceeds 100K tokens). No row when the report has zero tokens. The pipeline daily spend cap therefore includes director cost.
